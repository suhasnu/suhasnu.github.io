Who I am

I care about the pipeline that still runs on a bad day.

I came to data engineering through a year of it as a job. At Apponix Technologies in Bengaluru I worked on Airflow, dbt and BigQuery over production PostgreSQL databases and third-party SaaS APIs, which is where I learned that most of the work is not writing the transformation, it is making the thing survive late data, changed schemas and reruns.

Since moving to Germany for my Master’s at Hochschule Fulda, I have built several systems from scratch rather than from tutorials: an electricity market platform with a streaming path measured against its own batch path, an economic analytics project spanning two statistics authorities, and an agent runtime that survives being killed mid-run.

The thread through all of them is the same: I would rather a system refuse than guess. Measures that return blank when a question is ambiguous, markers that are never read as zero, tests that record a discrepancy instead of hiding it.

EU Economy Analytics

Five monthly Eurostat indicators for Germany and five comparators, plus German regional unemployment from Destatis, loaded into BigQuery, modelled with dbt, and published as a five-page Power BI report and a self-recalculating Excel briefing.

Rates, index levels and survey balances share one fact table, so the base measure refuses to aggregate rather than quietly averaging them. Summing the 400 districts gives 2,787,125 against a published national figure of 2,787,112, and a test records that difference instead of hiding it.

ENTSO-E Data Platform

A daily ELT for six European electricity bidding zones: Airflow into BigQuery, a dbt star schema on a DST-correct hourly grain, and a second path through Kafka and Spark Structured Streaming measured against the batch pipeline on identical days.

The backfill was the real test: 1,799 task instances with no failures, after working through genuine memory limits rather than shrinking the window until it fit.

Durable Agent Runtime

An agent runtime written without a framework: a typed state graph, SQLite checkpointing and write-ahead logging of every tool call, so a killed process resumes without repeating side effects and refuses undecidable cases for a human instead of guessing.

I ported the same agent to LangGraph and compared the two. On the crash the runtime survives, the port charged twice. That comparison is the point of the project.

Multi-tool Weather Agent

An agent answering German weather questions by writing SQL against a DuckDB warehouse built from DWD station archives, combined with live forecast data. Two custom MCP servers, a FastAPI gateway with SSE streaming, and a Streamlit interface.

Read-only SQL is enforced at the DuckDB engine rather than by matching strings, and a 14-check quality gate guards the bronze to gold layers.
